# 1. ReaProjectLink 解决什么问题

## 过场动画的音频是怎么拼起来的

做一段游戏过场动画时，对白、音乐、音效通常由不同的人，在各自的 REAPER 工程里制作。到了混音阶段，这些内容要汇总进一个工程里，和画面对齐后一起混。

这个"汇总"环节一直有几个老问题：

| 常见做法 | 问题 |
|----------|------|
| 把各部门的轨道直接复制进混音工程 | 插件跟着一起过来，混音那台电脑上缺插件、插件版本不同，工程打开就报错 |
| 各部门弹出 WAV，混音时手动导入 | 每次更新都要重新找文件、对位置、删旧的，改得越频繁越容易漏、越容易对错版本 |
| 用 REAPER 的 Subproject | 仍然要打开对方的工程文件，插件依赖和保存冲突的问题都还在 |
| 画面改了，口头通知各部门 | 有人用新画面、有人还在用旧画面，交上来的东西对不上，很难查是谁用了哪一版 |

## ReaProjectLink 的做法

ReaProjectLink 把"工作"和"交付"分开：

- 每个部门在自己的工程里随便怎么做，用自己习惯的轨道结构和插件；
- 做好之后，把要交的音频弹出成普通的 WAV，放在指定的轨道上，用 ReaProjectLink **发布（Publish）**；
- 混音工程**同步（Synchronize）**这份发布，音频按原来的位置自动摆好；
- 下次部门再发布新版本，混音工程同步一次，旧的那批音频被整批换成新的。

画面的方向正好反过来：混音工程把画面、Marker、Region 发布出去，各部门同步过来，大家对着同一版画面工作。

![ReaProjectLink 的两个方向](images/01-overview.png)

这里有两种工程：
- **Source Project**：对白、音乐、音效这些上游工程。负责发布音频，接收画面。
- **Master Project**：负责整合和混音的工程，一个项目通常只有一个。负责发布画面，接收各部门的音频。

两边之间不会互相打开、修改对方的工程文件，只通过共享目录里发布出来的文件交流。

## 几个关键特点

**保存不等于发布。** 你在 Source Project 里怎么改、存多少次，Master Project 都看不到。只有你主动 Publish 了，别人才拿得到。所以你可以放心地在自己工程里试来试去。

**每次发布都是完整的一版。** Publish 交出去的是当前所有交付音频的完整快照，不是"这次改了哪几条"。Master Project 同步时，会把上一版的音频整批换成这一版。

**每一版都留着。** 每次发布都会生成一个新的版本号，旧版本不会被覆盖。需要时，Master Project 可以同步回之前的某一版。

**插件不会跨工程。** 交出去的只有弹出好的 WAV。Master Project 那边完全不需要装你用的插件。

**画面变了不会自动改你的音频。** Master Project 发布了新画面，你会看到提示，但 ReaProjectLink 不会自动挪你的音频。是否需要调整、怎么调整，由你判断。

## 它不做什么

- 不是云服务。所有文件都放在团队现有的共享存储上。
- 不支持多人同时编辑同一个 `.rpp`。每个工程还是各自一个人负责。
- 不会自动根据画面修改对齐音频。
- 不会识别以前手动导入的音频。Master Project 里原来手动导入的 WAV，不会被认成某个部门发布的内容；要由 ReaProjectLink 管理，需要按流程订阅并导入。
